## Sisa pekerjaan

### Keamanan

1. **Tidak ada pembatasan laju.** Login, registrasi, dan penerbitan token reset
   bisa dipanggil berulang tanpa batas — email/username bisa ditebak paksa, dan
   pengiriman email bisa dijadikan alat spam. Belum ada satu pun penghitung.

2. **`email_verified` tidak pernah diperiksa.** Kolomnya ada di tabel `users`,
   `confirmation_token` juga, tidak ada yang membacanya. Login menerima akun yang
   emailnya belum terbukti dimiliki. Butuh alur verifikasi email dulu — SMTP-nya
   sudah siap (`npm run check-smtp`), tinggal alurnya.

3. **Kata sandi minimal 6 karakter** (diturunkan dari 8 atas permintaan). Kata
   sandi akun saat ini enam digit dan merupakan awalan dari kata sandi lama yang
   pernah masuk riwayat git. Repo lama akan dihapus, tapi kalau sempat publik
   anggap sudah tersalin.

4. **Ganti kata sandi tidak membatalkan sesi yang sudah terbit.** Sesi berupa JWT
   tanpa penyimpanan di server; pembatalan butuh daftar-cabut atau nomor versi di
   profil. Relevan kalau suatu saat ada indikasi akun dibobol.

nama **Cuan Bitkonek**, dan plakat di halaman masuk berukir **$** (gaya batu tetap

## Sudah selesai (27–28 Juli)

Pola yang berulang di sepanjang migrasi Supabase → PostgreSQL lokal: **panggilan
dikomentari, pesan sukses dibiarkan.** Ditemukan sembilan kali. Bukan error —
diam-diam tidak berfungsi sambil mengaku berhasil.

**Autentikasi**
- Login sama sekali tidak berfungsi (`landing.tsx` adalah satu-satunya form login
  untuk `/` dan `/login`) — disambungkan
- Registrasi tidak mendaftarkan apa pun — disambungkan, divalidasi `zod`
- Logout tidak menghapus cookie; `deleteSession()` ada tapi tidak pernah dipanggil
- Reset kata sandi menerima input lalu mengalihkan ke dashboard tanpa token,
  tanpa sesi, tanpa menyentuh database
- `/forgot-password` mengaku mengirim email padahal tidak ada pengirim
- `SESSION_SECRET` punya fallback yang tertulis di repo
- OAuth Google tanpa parameter `state` (login CSRF); access token tercetak ke log
- Login username tidak pernah ada — kolom `username` + pencocokan
  email-atau-username, keduanya tanpa membedakan huruf besar-kecil

**Otorisasi (pengganti RLS yang hilang)**
- `requireAccount()` / `requireSuperAdmin()`: `accountId` tidak lagi diterima dari
  client — sebelumnya user login mana pun bisa membaca workspace orang lain
- Suspensi akun ditegakkan di gerbang yang sama; kolomnya dulu hanya ditulis admin
  dan tidak pernah dibaca
- `update`/`delete` pada wallet, budget, debt, savings, category, transaction,
  loan_tracker di-scope ke workspace
- `updateWallet` berhenti menyusun SQL dari nama kolom kiriman client
- Superadmin tidak bisa menonaktifkan akunnya sendiri (akan mengunci diri permanen)

**Uang**
- `create_transaction` / `delete_transaction` — fungsi Postgres yang dipanggil
  kode tapi **tidak pernah ada** di database lokal; diimplementasikan ulang di
  TypeScript dengan `withTransaction`
- `updateTransaction` sebelumnya hanya `UPDATE amount, note` tanpa menyentuh saldo
- Pembayaran utang tidak memindahkan uang dan tidak pernah menandai lunas
- Kontribusi tabungan tanpa cek kepemilikan maupun kecukupan saldo

**Halaman** — sebelas halaman dari kerangka jadi berfungsi penuh, termasuk panel
admin yang digabung ke Pengaturan (`/user/admin` dialihkan, bukan dihapus).

**Deployment** — CI berhenti mendeploy ke Vercel (dua produksi berbeda isi),
`sql/init.sql` jadi sumber kebenaran schema, `supabase/` diarsipkan, lima skrip
Supabase mati dihapus, `.gitattributes` menghentikan seluruh working tree berubah
jadi CRLF.
